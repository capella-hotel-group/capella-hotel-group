## Context

The highlights carousel block (`blocks/highlights-carousel/highlights-carousel.js`) currently parses each card row assuming:
- `cells[0]` → image
- `cells[1]` → title
- `cells[2+]` → body paragraphs

The AEM document authoring structure has been updated so each card row now contains five cells, with the title at index 3 and body at index 4. An alt text cell at index 1 was also introduced, and index 2 is reserved/unused.

## Goals / Non-Goals

**Goals:**
- Map `cells[0]` → image (`<picture>` element)
- Map `cells[1]` → alt text, applied to the `<img>` inside the picture
- Map `cells[3]` → card title (`<h3>`)
- Map `cells[4]` → card body content (`<p>`)
- No changes to carousel behaviour, CSS, or DOM structure outside of card content

**Non-Goals:**
- Changing carousel animation, drag, or arrow logic
- Modifying CSS classes or layout
- Supporting any cell index other than 0, 1, 3, 4

## Decisions

### Read cells by index, not slice

**Decision**: Use explicit index access (`cells[0]`, `cells[1]`, `cells[3]`, `cells[4]`) rather than the previous `cells.slice(2)` approach.

**Rationale**: The new cell layout is a fixed contract from AEM's document model. Explicit indices are clear and match the spec exactly. The slice-based approach was too implicit and breaks with the new structure.

**Alternative considered**: Scanning cells by content type (e.g., look for a `<picture>` anywhere in the row). Rejected — too fragile and ambiguous when multiple cells might contain similar content.

### Apply alt text to `<img>` inside picture

**Decision**: Read `cells[1].textContent.trim()` and set it as the `alt` attribute on the `<img>` inside the cloned `<picture>` element.

**Rationale**: The `<picture>` element generated by AEM may have an empty or generic alt on the `<img>`. The authored alt text cell should override it for accessibility.

## Risks / Trade-offs

- **Existing authored pages with old column structure** → Cards will render with missing title/body until content is re-authored to the new layout. This is an accepted content migration concern outside the scope of this code change.
- **cells[2] reserved slot** → Ignoring index 2 is intentional per spec. If content authors accidentally put data there, it will be silently ignored. → Mitigation: document the cell contract in the block's README or authoring guide.
